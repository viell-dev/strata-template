# Security reporting

Optional starting points for documenting a working private vulnerability-reporting route. Choose
a component only after the adopting repository has a maintainer who will monitor reports and has
decided its support and handling policy. No license or programming language is implied.

| Variant | Use case |
| --- | --- |
| [github](github/README.md) | A public GitHub repository using private vulnerability reporting |

The component supplies the reporting instructions and setup checks. Supported versions, response
expectations, and how fixes are announced remain decisions owned by the adopter. Copying a policy
file does not enable reporting or configure notifications.

An ecosystem hub can instead link to the responsible repositories' policies, or describe an
explicitly agreed central process. Do not direct reports to a hub merely because it hosts the
ecosystem documentation; its maintainers must have agreed to receive and route those reports.
